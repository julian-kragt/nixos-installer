**Stage 0.1 — Provider preparation.** Runs on the provider, plus read-only checks on the target, which is still the NixOS ISO.

Purpose: be certain everything is in place before anything is wiped, collect the host facts later stages need, get the operator's explicit confirmation, and deliver the LUKS passphrase.

Expects: stage 0.0 passed (tools, network, key access to the ISO, config flake); `env.Host`, `env.Target`, `env.ConfigDir` are set;

Must do:
- Resolve the install disk here. It moves out of 0.0, which only checks the environment (see ROADMAP "Plumbing design"): `--disk`, else the disk recorded in State, a lone disk, or the operator's pick. `resolveDisk`, `listDisks`, `parseLsblk`, `chooseDisk` and their tests move from `00_environment_preparation*.go` into this stage's files, together with the "recorded disk differs" guard. Compare the recorded and the detected disk after `readlink -f` on the target, so a `/dev/disk/by-id/…` path matches the `/dev/<name>` that lsblk reports.
- Read facts with `nix.EvalHostInfo` (`nix eval --json <bootstrap>#installerData.<host> --override-input config <ConfigDir> --no-write-lock-file`): users, root's authorized keys, hardware config path.
- Before anything is wiped, check that at least one key from the provider's agent (`ssh-add -L`) is in `rootAuthorizedKeys` from those facts. Otherwise the installer cannot reach the installed system (password login is off).
- Check the config repo is a git repo with an upstream and has no uncommitted changes outside the paths the installer manages (the host's `hardwareConfigPath`, `flake.lock`), because only pushed config is installed in Phase 3.
- Evaluate `<bootstrap>#nixosConfigurations.<host>.config.system.build.toplevel.drvPath`: `installerData` does not check disko's options, NixOS's assertions or the hardware config.
- Read the devices from `<bootstrap>#nixosConfigurations.<host>.config.disko.devices.disk`. Confirm one equals `State.Disk` (after `readlink -f` on the target) and that every device is a block device on the target. The operator sets the device in the config by hand; on a mismatch fail with what to change.
- Target checks: `nix` and `lsblk` present, `https://cache.nixos.org/nix-cache-info` reachable.
- Show `lsblk` and the target hostname, then require the operator to type `install`.
- LUKS passphrase asked twice without echo (`runner.AskSecret`, which already exists); send it with `RunStdin` to `/tmp/disko-password` (mode 600) on the target. The legacy script also read `DISKO_PASSWORD` from the environment; say in your plan whether to keep that: every child process sees an environment variable, which is the reason for the rule against passwords in the environment, and a LUKS passphrase is the same kind of secret.

Introduces shared plumbing (design in ROADMAP "Plumbing design"):
- The `pipeline.Machine` output model. Capture stdout and stderr separately: `Run` returns stdout only, stderr is streamed to the runner and the log, and the error text comes from the stderr tail (today both streams are one buffer and the error quotes `lastLine` of it, so `nix eval --json` would break on a `warning:` line and a quiet command would leak its output into the error). Add `Quiet()`, a copy of the Machine that streams nothing and puts no output in its errors (RUNNER.md asks for this with the first secret command); the passphrase transfer is its first user. `TestRunCapturesAndStreamsOutput` changes accordingly.
- `pipeline.Loopback()`: a Machine whose "ssh" is the local shell (today the unexported `loopback` in `machine_test.go`), exported so tests of the tool packages and of stages can have a remote Machine. Make the target paths a stage uses (`/tmp/disko-password`) variables, so tests can point them at a temp dir.
- Tool helpers, each in its own package with functions taking a `pipeline.Machine` (not files in `internal/stages`, see CONTEXT §4): `internal/nix` for `nix eval --json`, `internal/git` for git (always `git -C`, commit listed paths only, only when there is a diff).

Changes stage 0.0: it no longer resolves the disk, and its root-password bootstrap (`setupSSHAccess`) runs only while 0.2 is not in `State.Completed`; afterwards a failed key login is an error, not a password prompt. Update `00_environment_preparation.go` and its test.

Writes State: `Disk` (saved when the stage completes). There is no `State.Users`: stages that need the user list read it from `installerData.<host>` themselves (ROADMAP "Plumbing design").
