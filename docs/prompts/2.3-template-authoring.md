**Stage 2.3 — Template authoring.** Runs on the provider; checks run on the target. Interactive.

Purpose: every secret file this host needs exists, is encrypted to the current recipients, and holds real values instead of template placeholders. The operator writes a file in vim on the provider and types its passwords; sops on the provider encrypts it to the public keys from `.sops.yaml`. The provider holds no key that decrypts it afterwards.

Expects: 2.2 (rules in place). `docs/ROADMAP.md` "Verified assumptions" says how sops decrypts with the host's age key on the target.

Templates (`<secrets>/templates/host.yaml`, `user.yaml`): a YAML mapping, nested to any depth. Every node that is not a mapping with keys is a leaf: a scalar, a multi-line scalar or a list. A leaf whose last key is `hashedPassword` is a password; a leaf holding `change_me` / `CHANGEME`, or empty (`""` or null), is a secret; any other leaf is a literal. Keys must be strings (quote `"0":`), as sops encrypts no other, and cannot hold `"`, `]` or `\`, which sops' `--extract` paths cannot express.

Built (`internal/secrets`, `internal/commands/sops`, `internal/commands/vim`, `runner.Hand`):
- `vim.EditUntil`: writes the buffer to a mode-600 file in a new mode-700 directory under `$TMPDIR`, opens `vim --clean -n -i NONE --cmd 'set noswapfile nobackup nowritebackup noundofile'` on the terminal (`runner.Hand` freezes the live area meanwhile), reads the file back and removes it as soon as vim exits. `:cq` aborts; an unchanged or rejected file offers "Edit again" (with the last text) or "Abort". Errors name key paths, never values.
- `Template.Buffer`: the template without its password leaves, under a comment saying what to do. `CheckEdited` runs `Check` on the edited text, without the passwords.
- `Document`: the edited mapping without comments (they would be encrypted), with each password's yescrypt hash (`mkpasswd`, prompt via `runner.AskSecretTwice`) set at its path; a top-level `sops` key is refused.
- `sops.Fields` on the target: the leaf paths come from the ciphertext, whose keys sops leaves readable; the target decrypts each with `sops decrypt --extract '["db"]["password"]'` and prints only its class (`placeholder`, `empty`, `crypt`, `value`), classified by shell builtins with the rules of `secrets.Classify`. The whole file is decrypted first: only sops' exit 128 (no key decrypts it) is `ErrCannotDecrypt`. An unreadable key file, another sops failure (with its exit code) and a path sops cannot extract are errors of their own, so 2.3 does not ask for the values again over them.
- `Check(template, fields)`: the same leaf paths as the template, no placeholder or empty value, a crypt hash for every password.

Must do, per file (`hosts/<host>.yaml`, each `host-users/<host>-<user>.yaml`):
- Exists, its recipients equal the rule's, and `Check(Fields)` passes → nothing; a re-run asks nothing.
- Anything else (missing, recipients changed, cannot be decrypted, check fails) → vim when the template has a secret leaf, a prompt per password, `Document`, `Encrypt`, then `Fields` and `Check` again as proof. There is no `updatekeys`: the provider cannot decrypt, so a changed file is written again in full.
- Plaintext lives in the installer's memory and, while vim is open, in that temp file only: never in an argument or the log.
