**Stage 0.2 — Base install.** Runs on the provider, acting on the target.

Purpose: install nixos-bootstrap's `nixosConfigurations.<host>` with nixos-anywhere, then wait for the installed system and pin its SSH host key.

Expects: stage 0.1 (config installs to the chosen disk, passphrase on the target).

Must do:
- Re-check `/tmp/disko-password`; ask again if it is gone.
- Skip nixos-anywhere when the target already runs the installed bootstrap system (hostname equals the host and it is not the ISO). The legacy `test -f /run/current-system` check never worked.
- nixos-anywhere cannot pass `--override-input`, so write a wrapper flake to a temp dir (nixos-bootstrap's INSTALL.md, step 3): input `nixos-bootstrap.url = <env.Bootstrap>`, `nixos-bootstrap.inputs.config.url = git+file://<ConfigDir>`, outputs inheriting `nixosConfigurations`, no lock file. From the root of `<ConfigDir>`, run `nix run github:nix-community/nixos-anywhere/<pinned ref> -- [--generate-hardware-config nixos-generate-config <HardwareConfigPath>] --build-on remote --flake <wrapper>#<host> --target-host root@<ip>`, output streamed to the runner. `hardwareConfigPath` is relative to the config root and must already exist; stage 0.1 generates it from the target for a new host. Always generate it; there is no flag for this.
- Install only from the ISO. nixos-anywhere 1.13.0 skips kexec when `/etc/os-release` has `VARIANT_ID=installer`, so `/tmp/disko-password` from stage 0.1 survives and `--disk-encryption-keys` is not needed. A kexec would lose the file, so refuse any other system that is not the host.
- Commit the file at `HardwareConfigPath` in config, listed paths only, only if changed, then push. Push even without a new commit, so a re-run retries a push that failed.
- Wait for SSH: poll every 5 s for up to 15 minutes (a constant, not a flag), tell the operator to type the LUKS passphrase at the console, accept only a host key that differs from the ISO's, show its fingerprint.

Introduces shared plumbing (design in ROADMAP "Plumbing design"):
- Host key pinning. It replaces both `StrictHostKeyChecking=no` in `pipeline.SSH` (`machine.go`) and `ssh.InsecureIgnoreHostKey()` in `InstallAuthorizedKeys` (`authorized_keys.go`); both carry a TODO (see CONTEXT §7 "Host key"). Pins are keyed by host name (`HostKeyAlias=<host>`) in a per-host known_hosts file under the state dir, not by IP: the target IP is a per-run input and can change between the ISO and the installed system. The ISO's key is pinned at first contact in 0.0, with its fingerprint shown, so a swapped target is noticed before the LUKS passphrase is sent. After first boot the installed system's key replaces it (TOFU) and every later connection checks against it. nixos-anywhere cannot be given the pin: its own `StrictHostKeyChecking=no` comes first and ssh takes the first value of an option. Check the pin over the stage's own connection right before starting it.
- `pipeline.NewEnv(inputs, state)`, which builds Local and Remote from the inputs and the State (pinned or not), which keeps the pin next to the state file. Today `main.go` builds `Remote` from the IP alone.
- No `ControlMaster` by default. OpenSSH applies the master's `ForwardAgent` to the sessions multiplexed over it (verify), which conflicts with the opt-in agent forwarding of 3.2. If it is used after all (measured slow), put the forwarding mode in `ControlPath` and keep the path short: macOS limits socket paths to 104 bytes.

Writes State: `HostKeyFingerprint`.
